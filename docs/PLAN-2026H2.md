# GAX plan — 2026 H2

**Status:** draft · **Owner:** @0sparsh2 · **Created:** 2026-07-29

Two tracks, run in this order:

- **Track A — Repositioning.** Fix what GAX claims to be. The token thesis expired; the enforcement thesis did not.
- **Track B — Eval integrity.** Fix four defects in the harness that inflate GAX's numbers. W2 → W1 → W4 → W3.

Track A goes first because it determines what the eval needs to prove.

---

## Context: why this plan exists

Two independent findings triggered it.

**1. A code review of the eval found four defects**, all pointing the same direction (favorable to GAX):

| # | Defect | Effect on published numbers |
|---|--------|------------------------------|
| W1 | `cli` median over 7 tasks, `gax` median over 15, only 6 shared | Published ratio 1.3×; true paired ratio ~2.9× |
| W2 | `_apply_expected_outcome` flips 32/150 rows to `ok=True` | Every modality reports `success_rate: 1.0` |
| W3 | Mock MCP (1 tool, 93 tok) tabled beside live MCP (26 tools, 4,489 tok) | CI publishes the flattering figure |
| W4 | `mcp_naive_43` and `gax_ablation_schema_preload` are a borrowed constant + arithmetic | Most-cited contrast is not a measurement |

None are dishonest in intent — `METHODOLOGY.md` and `PUBLIC_NARRATIVE.md` already disclose bias, refuse a weighted composite, and correctly restate Scalekit's 28%. The defects are in the aggregation, which quietly does favorable work the prose disclaims.

**2. Market research (July 2026) found the token premise has expired.**

| What changed | Evidence |
|---|---|
| Lazy discovery is now a platform feature | Anthropic [Tool Search Tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) with `defer_loading: true`, ~85% token reduction; accuracy gains too (Opus 4.5: 79.5% → 88.1% on MCP evals). OpenAI shipped defer-loading as well. |
| Code Mode is mainstream | Up to [92.8% lower input tokens at 500+ tools](https://www.getmaxim.ai/articles/code-execution-with-mcp-how-code-mode-cuts-agent-token-costs-by-90/) at 100% pass rate |
| MCP won the standards war | [Donated to Linux Foundation AAIF Dec 2025](https://chatforest.com/guides/mcp-ecosystem-2026-state-of-the-standard/); OpenAI, AWS, Google, Microsoft, Cloudflare, Bloomberg members; 97M downloads, 6,400+ servers |
| Gateways became a funded category | [Docker, Cloudflare, Kong, Bifrost, Lunar, MintMCP, TrueFoundry](https://www.truefoundry.com/blog/best-mcp-gateways) all ship policy + audit + OAuth |

GAX Invariant #1 (lazy discovery instead of schema preload) is now shipped by the model vendors. The 44k-token villain was retired by the people who created it.

**What did not get solved** — and where GAX already has working code:

1. **Governance is the acknowledged gap in the standard.** The [MCP 2026 roadmap names enterprise governance, audit trails and SSO auth as priorities it does not yet address](https://blog.gitguardian.com/mcp-governance-framework/). [30+ CVEs in Jan–Feb 2026](https://chatforest.com/guides/mcp-ecosystem-2026-state-of-the-standard/): Asana cross-tenant leak, Smithery path traversal (3,243 apps), tool poisoning.
2. **Nobody governs the shell.** Every gateway listed governs MCP traffic. Agents act overwhelmingly through `bash` — Claude Code is file access + bash + MCP. An MCP gateway sees none of it. [NVIDIA OpenShell](https://www.tigera.io/blog/nvidia-openshell-secures-the-agent-who-governs-the-fleet/) (GTC 2026) validates the problem but works at the syscall layer, with no notion of registered command + capability + audit record.
3. **Enterprise deals die on this question.** Per the research: Series A–C AI startups lose deals because they cannot answer agent-governance questions. The emerging best practice — *"if the audit write fails, the tool call should fail"* — is exactly what [`gax/gax/executor.py`](../gax/gax/executor.py) implements.

**Verdict:** relevant as a runtime, not as a rival protocol. Kill ACSP-as-competing-standard (it puts us against the Linux Foundation, OpenAI, Google, AWS and Anthropic simultaneously, on the axis where they already shipped the fix). Keep the enforcement runtime. GAX Invariant #4 — *no arbitrary shell, only registered commands* — is the most valuable thing in the repo and is barely mentioned in the README.

## Track A — Repositioning

### A1. README rewrite

**From:** "a third surface competing with MCP and CLI, saving you a 44k token tax."
**To:** "the governed execution layer for agent shell commands — complements MCP, covers what MCP gateways can't see."

Mostly a docs change; the code already does this.

| Element | Change |
|---|---|
| Lede | Lead with the shell-governance gap, not token economics |
| Token section | Demote to secondary; explicitly concede tool search / code mode closed most of the gap |
| MCP framing | From "we replace MCP" to "we govern MCP calls *and* shell calls through one policy file, one capability model, one audit trail" |
| Invariant #4 | Promote to the headline claim |
| Envelope v1 | Justify as audit correlation + uniform error handling, not token savings |
| ACSP | Demote to internal envelope spec; drop standards-bid language |
| Eval table | Placeholder until Track B lands, then paired numbers |

**Acceptance:** a reader who knows tool search exists does not bounce. No claim in the README depends on the 44k tax being unsolved.

**Risk:** conceding the resolved problem sounds like weakness. It isn't — it signals we track the field, and it's the difference between a repo that survives a knowledgeable reader and one that doesn't.

### A2. GAX as an MCP server — ✅ **SHIPPED**

[`gax/gax/mcp_server.py`](../gax/gax/mcp_server.py) · entry point `gax-mcp` · 15 tests in [`test_mcp_server.py`](../gax/tests/test_mcp_server.py)

```bash
claude mcp add gax -- gax-mcp
```

Exposes exactly three tools — `gax_search` / `gax_doc` / `gax_invoke` — keeping the
registry behind them, so the schema surface is **constant-size regardless of registry
growth**. That is the same shape as tool-search / `defer_loading`, so it composes with
the platform fix rather than competing with it.

- Any MCP client (Claude Code, Cursor, OpenAI Agent SDK) gets governed shell execution with zero integration work
- Inherits MCP distribution (6,400 servers, 97M downloads) instead of fighting it
- ACSP survives internally as the envelope spec
- Stdlib-only stdio JSON-RPC — **no new dependency**

**Verified:** `initialize` / `tools/list` / `tools/call` conformance; notifications get no
response; malformed JSON doesn't kill the session. Governance boundary holds through the
new surface — out-of-capability commands → `policy_denied`, unregistered → `not_found`,
missing cap → `capability_invalid`, and every invoke writes a correlated `audit_id` to
`~/.gax/audit.jsonl`. CI runs both the unit tests and a real stdio subprocess round-trip.

**Remaining:** the `tools/list` response does not yet emit per-tool `defer_loading`
hints — unnecessary at three tools, worth adding if the surface ever grows.

### A3. The demo that makes the argument

90-second video: an agent does something destructive via `bash` that a Docker/Cloudflare/Kong MCP gateway logs **nothing** about; GAX denies it pre-invoke with an audit record.

Pair with tool poisoning: GAX's registered-commands-only model is structurally immune to a poisoned tool description, because the model can only name commands already in the registry.

### A4. Wedge — regulated CI/CD

Not "enterprise agent governance" broadly; that's where the funded gateways live. Target where shell is unavoidable and audit is mandatory: agents running deploys, migrations, `kubectl`, Terraform under SOC2/FedRAMP. `gax compliance export` already exists in prototype.

**Roadmap honesty:** Vault/SPIFFE/OPA are stubs and the narrative says so. For this wedge **OPA must become real** — policy-as-code is table stakes. Cut Vault and SPIFFE from the pitch until genuine; the current honesty is an asset that becomes a liability if the narrative outruns the code.

**Explicitly not doing:** competing on breadth of integrations. Composio, StackOne, Docker's 200-image catalog win that permanently. Win on depth of the enforcement guarantee for a narrow, high-stakes surface.

## Track B — Eval integrity

Order: **W2 → W1 → W4 → W3.** W2 first because W1's paired logic depends on knowing which rows genuinely succeeded.

Each workstream has a **planner gate** (decisions before code) and an **evaluator gate** (how we know it worked).

### W2 — Decompose `success_rate` *(do first)*

**Defect:** [`_apply_expected_outcome`](../eval/run_comparison.py) rewrites `ok=True` whenever the outcome matched expectation, including expected *failures*. 32 of 150 rows are flipped. Every modality lands at `success_rate: 1.0` except ablations. The metric measures nothing.

**Planner decisions:**

1. Split into three orthogonal axes:
   - `completion_rate` — adapter returned without error
   - `expected_outcome_rate` — result matched the task's declared expectation (incl. expected failures)
   - `fail_closed_rate` — error-category tasks only: did enforcement trigger *before* the adapter ran?
2. `audit_id_rate` / `structured_envelope_rate` are architectural constants (CLI is 0% by definition). Move under a **"by-design properties"** heading, out of the results table. They are design claims verified by test, not measurements.
3. Preserve traceability: keep `ok_raw`, `ok_adjusted`, `adjustment_reason` on every row.

**Build:** rewrite `primary_metrics` and `aggregate_by_modality` in [`eval/scoring.py`](../eval/scoring.py).

**Evaluator gate:**
- No modality reports 1.0 across all three axes unless genuinely earned
- `fail_closed_rate` for `gax` on `policy_denied` = 1.0; for `gax_ablation_no_cap` = 0.0 — this is the ablation's actual point and must be legible in the numbers
- **Acceptance:** a reviewer can tell from the table alone which numbers are measured vs. definitional

### W1 — Paired-task comparison *(the headline fix)*

**Defect:** modality medians are computed over different task subsets.

- `cli` median 113 ← 7 tasks
- `gax` median 140 ← 15 tasks
- Only **6 overlap**

The 9 gax-only tasks (`echo`, `kubectl_mock`, `aws_mock_list`, `jira_mock_get`, `discovery_only`, `search_stub`, `policy_denied`, `unknown_command`, `large_output_truncation`) are cheap mocks and discovery stubs (23–143 tokens) with no CLI equivalent by construction. They drag the gax median down.

**Paired comparison on the 6 shared tasks:**

| task | cli | gax | ratio |
|---|---:|---:|---:|
| pr_view_first | 36 | 158 | 4.4× |
| pr_view_invalid_number | 43 | 128 | 3.0× |
| pr_list_invalid_repo | 61 | 134 | 2.2× |
| multi_turn_pr_workflow | 113 | 589 | 5.2× |
| pr_list | 127 | 467 | 3.7× |
| cli_bad_flag | 263 | 347 | 1.3× |
| **median** | **87** | **252** | **~2.9×** |

**Planner decisions:**

1. Comparison unit: a task is comparable for a modality pair iff **both** produced a non-skipped row. Compute pairwise, not globally.
2. Report **both** median ratio (headline) and per-task ratios (distribution) — n=6 is too small for a median alone to carry weight.
3. gax-only tasks do **not** vanish. They are legitimate capability evidence (policy denial, discovery) and move to a separate "GAX-only capabilities" section, out of the token table.

**Build:**
- `paired_comparison(rows, mod_a, mod_b)` in `scoring.py` → per-task ratios, median ratio, n, excluded-task list with reasons
- New `comparison.json` key: `paired_by_modality_pair`
- `comparison.md` leads with the paired table; all-task aggregate stays, labelled *"different task subsets — not a like-for-like comparison"*

**Evaluator gate:**
- For every pair: `n_paired ≤ min(n_a, n_b)`, and every paired task is non-skipped in both
- Golden test on the current dataset: cli↔gax paired median ratio ≈ 2.9× (guards against silent regression to set-mismatch)
- **Acceptance:** README, `PUBLIC_NARRATIVE.md`, `live-run-summary.md` and the gist all state the paired number. `grep -rn '104\|137'` finds no stale copies.

### W4 — Reframe fixture-derived modalities

**Defect:** `mcp_naive_43` = transcript + a 44,026 constant read from Scalekit's blog ([`mcp_schema_tokens.json`](../eval/fixtures/mcp_schema_tokens.json)); the schema blob in the transcript is a placeholder string. `gax_ablation_schema_preload` = gax + the same constant, so it can only ever show that adding 44k costs 44k.

**Planner decisions:**
1. `mcp_naive_43` is a **model**, not a measurement → rename `mcp_naive_43_modeled`
2. **Drop** `gax_ablation_schema_preload` — arithmetic, not an ablation
3. Promote `mcp_live` to primary MCP comparator (genuinely measured, 4,483)
4. Add `derivation: measured | modeled_from_fixture` to every row

**Evaluator gate:** every row carries `derivation`; no headline table mixes the two without labelling. **Acceptance:** the most-cited contrast in the repo is a measured number.

### W3 — Separate mock from live MCP

**Defect:** `mcp_live_mock_github` (93 tok, [1 tool](../eval/mock_mcp/github_stdio_mock.py)) sits in the same table as `mcp_live_github` (4,489 tok, 26 tools) — a 48× gap distinguished only by a `status` column. CI runs `--mock-only`, so CI-published numbers are the flattering ones.

**Planner decision:** keep mocks (CI needs secret-free runs) but rename prefix to `mcp_ci_mock_*` and emit to a separate table stating they measure harness plumbing, not MCP cost.

**Build:** rename modality prefix; split `_write_extended_report` into "measured (live)" and "CI plumbing (mock)"; add `is_mock: true`.

**Evaluator gate:** test that no mock row aggregates into a modality whose name lacks the mock marker. **Acceptance:** `--mock-only` output carries a visible banner that token figures are not representative.

After Track B, the headline moves:

That sounds weaker. Take it anyway:

1. It survives a hostile reviewer; the 1.3× does not.
2. Tokens are no longer where the argument should be fought (Track A).
3. Publishing the unflattering paired number ourselves is worth more reputationally than the number costs us.

### P0 — destructive commands + side-effect ceiling ✅ **SHIPPED**

Closes the honest catch: `deny_destructive` was dead code because no manifest had ever
declared `destructive`, so the branch never executed.

- [`side_effects.py`](../gax/gax/side_effects.py) — `read` → `write` → `destructive` ladder;
  unknown levels and missing ceilings **fail closed**
- [`k8s_adapter.py`](../gax/gax/adapters/k8s_adapter.py) — `k8s.pod.delete` (destructive),
  `k8s.deployment.scale` (write), `k8s.pod.list` (read); argv-only (no shell), DNS-1123
  validation before exec, server-side `--dry-run`, `GAX_K8S_MOCK=1` for cluster-free demos
- Capabilities carry `max_side_effect` (default `read`), enforced in
  [`policy.py`](../gax/gax/policy.py) **independently of the command allowlist**
- `deny_destructive` became a tenant-level kill switch overriding any capability
- CLI options now **derive from `input_schema`** — new manifests get working flags with
  no code change (they were previously hardcoded to six)
- `cap-mint --raw` fixes the quoting papercut that silently produced broken tokens
- 26 adversarial tests; CI gained an e2e refusal check

**Verified end-to-end** through both the CLI and the MCP surface, with denials audited
to `~/.gax/audit.jsonl` including arguments.

### P2 — on-ramp ✅ **SHIPPED**

Measured the old path in a clean virtualenv first: a new engineer hit **two dead ends**
(bare `[Errno 61] Connection refused`, then `missing capability token`) before their
first successful command. Now: **4 seconds**, zero dead ends.

- [`onboarding.py`](../gax/gax/onboarding.py) — `gax init` (idempotent: `~/.gax`, random
  signing secret, 30-day **read-only** capability at `0600`, starts the sidecar) and
  `gax doctor` (config, capability expiry + ceiling, sidecar, backends, audit log;
  every failure prints the command that fixes it)
- CLI falls back to the saved capability, so the first command needs **no exports**
- Connection and missing-capability errors now name the fix instead of surfacing errno

**Two bugs the clean-install test caught that were invisible from the repo** — a
`pip install -e .` checkout hides both:

1. **The wheel shipped no `config/policy.yaml`.** `pip install gax` loaded an *empty*
   policy — every tenant allowlist silently gone. Data now lives inside the package
   (`gax/paths.py` prefers the packaged copy, falls back to the repo layout), and
   `include-package-data = false` stops setuptools sweeping stray copies into the
   wheel root.
2. **A daemon from a different `~/.gax` failed every call** with `Signature
   verification failed` — reads like a bad token, is actually a stale process.
   `/health` now returns a `config_fingerprint` (never the secret) and both `init`
   and `doctor` flag the mismatch.

CI gained a wheel-install job that asserts the policy survives packaging and that the
first run works in a fresh `$HOME`.

### P3 — command profiles ✅ **SHIPPED**

Closes the last adoption gap: GAX shipped 11 mostly-mock commands, so a new user's
first task was authoring YAML. A framework that ships empty doesn't get adopted.

- [`profiles.py`](../gax/gax/profiles.py) + `gax profile list` / `gax profile add`
- **`k8s`** (6) and **`github`** (5) profiles, each spanning `read` → `write` →
  `destructive`, so the ceiling is exercised rather than theoretical
- Installs into `~/.gax/manifests/`, which the registry loads *after* the packaged
  set and lets win on conflict — profile commands survive upgrades and local edits
  are never clobbered (`--force` to overwrite)
- Both adapters became table-driven: a new manifest needs one dispatch entry, not
  an `if` branch
- **Installing grants nothing.** `init --profile k8s` adds only the profile's *read*
  commands to the dev capability; write/destructive stay refused until minted for
  deliberately. 20 tests pin this, including end-to-end denial with an `audit_id`.

**A third packaging bug surfaced:** `sync_package_data.py` leaves copies at
`gax/gax/<name>/`, and `paths.py` preferred them — so editing `config/policy.yaml`
appeared to do nothing until the next sync. The repo copy now wins when both exist;
installed wheels have no repo copy and are unaffected.

**Clean-env measurement:** `gax init --profile k8s --profile github` → **22 registered
commands, ~1 second**, with `k8s.namespace.delete` and `gh.pr.merge` both already
refused.

### Move 1 — pinned MCP import ✅ **SHIPPED**

Turns the ~6,400-server MCP ecosystem from competitor into addressable surface, and
closes the tool-poisoning CVE class.

```bash
gax mcp import --id filesystem npx -y @modelcontextprotocol/server-filesystem /tmp
gax mcp verify
```

- [`mcp_pin.py`](../gax/gax/mcp_pin.py) — SHA-256 over the tool's **name, description,
  and inputSchema**. Description is in scope because it is *instructions to the model*:
  rewriting it changes agent behaviour with the schema untouched, which is the actual
  injection vector. Presentation metadata (title, annotations, outputSchema) is excluded
  so honest version bumps don't raise false alarms.
- [`mcp_import.py`](../gax/gax/mcp_import.py) — enumerates `tools/list`, writes one
  namespaced manifest per tool (`mcp.<server>.<tool>`) with the pin recorded
- Enforced in [`mcp_bridge.py`](../gax/gax/adapters/mcp_bridge.py) **before** the tool
  call; mismatch → new error kind `pin_mismatch`, exit code 6, `retryable: false`,
  audited with its own kind so tampering is greppable
- Import defaults to `side_effects: destructive` unless the tool is clearly read-only —
  a stranger's tool cannot be reached by the read-only dev capability until a human
  reviews it. Re-import never silently re-pins, so tampering can't be laundered.

**Verified against a server that mutates**
([`mutating_stdio_mock.py`](../eval/mock_mcp/mutating_stdio_mock.py)) — poisoned
description, added parameter, rename, and disappearance are each refused pre-invoke,
while the honest server works. 29 adversarial tests; CI runs the e2e tamper check.

**Caught while building:** the manifest truncates `description` to 300 chars for
display, so diffing a mismatch against it reported an honest long description as
tampered. The exact canonical form is now stored as `mcp_pinned_tool` and used for
comparison. The pin itself was always correct; only the diagnostic was wrong.

A2 was pulled forward ahead of W3/W4: it is the item that makes the repositioning
concrete rather than rhetorical, and the remaining eval work is small by comparison.
